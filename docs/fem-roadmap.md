# PDE/FEM architecture and evidence gates

Updated **26 October 2026**. The recommended core is **DOLFINx/UFL + Gmsh/OpenCASCADE**, with an independent **GetDP** comparison and a measured decision about **MFEM** when throughput becomes limiting. The new [complete-electrode implementation](fem-complete-electrode.md) is a verified small reference. It is not yet a production, distributed or state-of-the-art anatomical MREIT solver.

## Roles for the four technologies

| Technology | Role in this program | Decision and evidence |
|---|---|---|
| **DOLFINx / UFL / Basix** | Variational PDEs, tensor materials, higher-order spaces and the future PETSc block solver | **Adopted.** CG1/CG2 CEM is implemented and tested. DOLFINx exposes Gmsh physical tags and distributed mesh import; our current solve is explicitly serial. [Gmsh interface](https://docs.fenicsproject.org/dolfinx/main/python/generated/dolfinx.io.gmsh.html), [official assembly example](https://docs.fenicsproject.org/dolfinx/main/python/demos/demo_pyamg.html) |
| **Gmsh + OpenCASCADE** | Parameterized phantom/electrode CAD, conforming material interfaces, boundary tags and graded meshes | **Adopted.** Boolean fragments imprint finite electrodes and the layered interface. OpenCASCADE is the CAD kernel, Gmsh the mesh generator; neither replaces the PDE solver. Curved phantom/head geometries will need geometry-order and mesh-quality checks. [Gmsh manual](https://gmsh.info/doc/texinfo/) |
| **GetDP** | Independent formulation and implementation for electrical, magnetic and circuit comparisons | **Next independent FEM reference.** Its nodal/edge/face elements and lumped-circuit coupling suit complete-circuit verification. Match mesh, material tensors, contact law, gauge and current definitions before comparing outputs. The site lists stable 3.5.0 (2022) and ongoing development snapshots; release age alone does not establish inactivity. [Official project](https://getdp.info/) |
| **MFEM** | High-order matrix-free/partial-assembly solves and GPU throughput for large forward ensembles | **Benchmark before adopting a second production backend.** MFEM supplies high-order H1/H(curl)/H(div), adaptive meshes and GPU infrastructure. Measure end-to-end time, memory and accuracy on our actual tensor-CEM workloads; GPU support alone does not establish a benefit. [Features](https://mfem.org/features/), [GPU support](https://mfem.org/gpu-support/) |

Existing work also matters: [ti-sim](https://github.com/m9h/ti-sim) already has a Gmsh/OpenCASCADE sphere builder and documents DOLFINx/SimNIBS comparisons. We inspected its mesh script and replication notes. The referenced `neurofedora/ci/conductivity-admm/sphere_ti_forward.py` was absent from the local neurofedora checkout, so those reported comparisons have **not** been rerun or counted as validation of this CEM implementation. Shared mesh/tag/current conventions are the immediate reuse opportunity.

## Ordered implementation gates

1. **CEM and independent physical oracles — delivered for small tanks.** Finite electrode patches, contact impedance in Ω·m², scalar and symmetric positive-definite tensor conductivity, CG1/CG2, material-conforming CAD, electrode current and power identities, reciprocity, rotation, polarity and gauge tests. Full-face homogeneous/layered results match analytical resistance; the layered case also matches the independent FV code after removing the contact drop. Finite-patch h/p voltage refinement is recorded, without claiming a certified field error.
2. **Conservative current and error-controlled refinement — next coding ticket.** Implement an equilibrated Raviart–Thomas/BDM reconstruction or mixed H(div) formulation. Require cellwise charge balance, normal-current continuity at tissue interfaces, correct electrode flux and a consistent power budget. Add manufactured tensor problems with nontrivial fields, mesh-quality checks and residual/goal-oriented estimators. Compare geometry, h and p errors separately. Electrode-edge refinement is currently a prescribed distance field, not an adaptive error estimator.
3. **Independent FEM and complete-circuit B.** Reproduce the CEM on the same tagged mesh in GetDP; report voltage, energy and spatial E/J errors. Specify both outgoing and return leads and electrode connections before computing B. Verify magnetic quadrature against closed-loop limits and refinement; then judge error in B parallel to B0 and encoded MR phase, not only the potential norm. No tank-derived B field is released yet.
4. **Scalable linear algebra.** Keep the verified direct solver as a small-case oracle. Add PETSc block/Schur treatment of field/electrode unknowns, explicit nullspace/gauge handling, AMG and MPI. Test one-rank/multi-rank agreement and strong/weak scaling, including assembly, communication, memory and solver tolerance. Only then compare MFEM partial assembly on CPUs/GPUs at matched observable error.
5. **Differentiation and inference.** Add implicit/adjoint derivatives for conductivity and contact parameters; validate with Taylor remainder tests, directional finite differences and reciprocity. Preserve SPD tensors through an explicit parameterization. A JAX-facing interface should differentiate the converged PDE solve, with solver tolerances in the gradient budget. UFL syntax or a JAX wrapper alone does not prove an adjoint correct. Separate conductivity, contacts, electrode position and current calibration in identifiability tests.
6. **Measured validation and open benchmarks.** Freeze versions, meshes, material/contact measurements and solver tolerances; predict held-out phantom injections and Prisma phase data from measured waveforms/timing. Publish raw observations and uncertainty, not only reconstructed maps. Diffusion-derived orientation information is a candidate prior, not an automatic electrical-conductivity calibration.

These gates define what would substantiate a SOTA claim: independently checked accuracy, conservative fields, observable-level error control, validated derivatives, measured scaling and predictive experiments. The framework choice supplies tools for that work; the benchmark evidence must establish the result.

## Environment decision

The local Apple-silicon run uses the official **pinned beta wheels** `fenics-dolfinx==0.12.0.dev202610191637`, Gmsh 4.15.2 and SciPy 1.18.1, in a separate environment. These DOLFINx wheels do not include PETSc. The [official installation guidance](https://github.com/FEniCS/dolfinx/blob/main/README.md) recommends conda, Linux packages, Docker or Spack for PETSc-enabled configurations. Promote a reproducible stable/container or HPC build with PETSc when implementing gate 4; do not silently treat this development wheel as a production release.
